# V3 多 CDN 测试版

2026-10-01：在V2已完成的播放器桥接、Auto并发及有限RAM缓存上增加独立RangePoolDownloader。Multi-CDN为独立实验模式，默认OFF，音频不进入分片池；原Auto/CDN优选仍保留。

## 资源准入
使用当前视频源的强ETag和精确总长度，最多验证2个备用URI。每个头64 KiB和尾64 KiB采样都必须满足If-Match、相同强ETag、206和相同总长度，并与主源字节一致。整个建池8秒deadline、逐请求4秒，不支持重定向或完整文件替代分片；无法满足则拒绝备用源。没有强ETag保持单连接代理。头尾采样不是整个文件的密码学相等证明；运行期间仍依赖CDN正确遵守强validator语义。不同validator不混用。

## 调度与生命周期
非round-robin：按较保守的快/慢吞吐EWMA、TTFB和在途数量估计完成成本，优先分配到更快且负载低的线路。片失败只对暂时错误进行最多一次跨线路failover，原offset不变；失败线路cooldown30秒，期满后重新参与有限需求任务。协议、ETag变化、403/429等终止并恢复原始播放。403恢复后使用现有去重回调请求刷新playurl，不无限重复授权请求。

Auto从4路逐级增加到16，buffer恢复逐级降低；session cache精确绑定原representation而不是候选URI。seek/网络变化/退出取消旧代；网络变化清pool和缓存。建池90秒TTL，同资源请求复用状态；新ETag/URI/长度重建。缓存8 MiB，重排4 MiB，不进行整视频RAM下载或后台磁盘下载。

## 诊断
提供actual/requestedConcurrency、parallelStatus、active/queuedRanges、reorder/cacheBytes、cacheHits及每条pool线路的throughput/TTFB/error/timeout/weight/cooldown/active。RTT未测保持null。吞吐采用视频输出实际3秒窗口，不将逐连接速度相加；cache输出并非新网络goodput，音频仍直连。不输出签名URL或本地私有token。

## 验证边界
localhost覆盖准入一致性、同ETag但头尾内容变化、按完成成本择线、暂时错误failover/cooldown、403不放大重试、取消、cache复用；原生Windows mpv验证单连接、4路和16路多CDN的EDL视频+直连音频、seek、源恢复、暂停与倍速。
Android测试APK执行插件注册、ZIP CRC、签名与16 KiB页对齐检查。所有模式保留真实视频长播、后台/PiP、网络变化及OFF/ON效果对照验收，合成测试不等于这些实机结果。其他平台未做本轮实机验收。
